# Precision check before v0.2.0 (2026-10-09)

A spot-check of what the shipped queries report on the five-project corpus, done before
the first release meant for external testers. The question for each sampled result: is
it what the query's message says it is? The Task 9.6 triage
([phase9.6-corpus-triage.md](phase9.6-corpus-triage.md)) sampled results before most of
its own fixes and before Phase 12; this check samples what is reported now.

## Method

Results come from `scripts/corpus_queries.py` (SARIF in `~/corpus-sarif`). For each query,
results were drawn with a fixed seed (`random.Random(42)`), ten per judgement query, or
all of them where there are fewer, and fewer for pattern queries, whose results are true
by construction once the pattern is right. Each was read against the source: for
"never used" queries, every occurrence of the name in the file; for control-flow
queries, the code after the reported line; for anything doubtful, the declarations
involved.

Most false positives come from two causes: code that is intentionally the way it is
(junk names, callbacks, coverage markers, side-effecting conditions), and names that do
not resolve because the project's dependencies are not in the corpus build. The
second affects testers too: a database built without all of a project's dependencies
resolves less.

## Fixes

Each has a fixture case that the previous query fails (`ql/test/queries/<query>/`).

- **Junk names** (`BasicDecl.hasJunkName()`): `unused-local` and `unused-parameter` skip
  names containing *discard, dummy, ignore, junk, unused*, as GNAT's own "never
  referenced" warning does.
- **Imposed profiles** (`Subprogram.hasImposedProfile()`): `unused-parameter` skips the
  parameters of a subprogram whose `'Access` is taken or that is a generic actual.
- **Unresolved `No_Return` calls**: `function-missing-return` does not count a path that
  goes through a call that did not resolve but is spelled like a `No_Return` subprogram
  and like no other (D-026's text fallback). `BasicDecl.hasNoReturnMark()` and
  `Subprogram.isNoReturn()` are now public; the CFG uses the same predicate.
- **`dead-local-subprogram`** skips `overriding` subprograms, subprograms an
  instantiation in the same body may use as an `is <>` default, and ones named by an
  instantiation actual that did not resolve.
- **`open-without-close`** reports a file only if it is held by an object local to the
  subprogram, not a parameter or an outer object.
- **`unreachable-statement`** skips pragmas, and statements in a `finally` part.
- **`useless-if`** skips an `if` whose condition contains a call.
- **`boolean-literal-comparison`** reports only when the other operand is known to be of
  a boolean type. This loses two true positives on the corpus, comparisons whose operand
  is a call that did not resolve; on a fully resolved project they are reported.

## Effect on the corpus

| Query | Before | After |
|---|---|---|
| unused-local | 199 | 129 |
| unused-parameter | 73 | 53 |
| unreachable-statement | 33 | 19 |
| function-missing-return | 17 | 3 |
| dead-local-subprogram | 25 | 18 |
| useless-if | 11 | 7 |
| boolean-literal-comparison | 4 | 1 |
| open-without-close | 34 | 32 |

Corpus total 2,306 to 2,172 (`scripts/corpus_query_baseline.json`). No query gained a
result; every other query is unchanged. Each removed result was checked to be one of the
patterns above.

## Left as they are

- **`function-missing-return`, 1 false positive** in libadalang-tools' testsuite: a
  second copy of the same unit declares the procedure without `No_Return`, so the name
  is ambiguous and the fallback rightly does not apply.
- **The CFG does not model GNAT's `finally` parts**, so data flow does not see the
  statements in them either. Recorded in BURNDOWN.
- **Test inputs dominate some counts.** gpr2's 566 `goto` results are generated lexer
  code, and most `empty-loop-body` and `self-comparison` results are pretty-printer test
  inputs. They are true positives; a tester who wants to exclude generated or test code
  can do it in their CodeQL configuration (`paths-ignore`).
