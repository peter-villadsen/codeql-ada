# dbscheme generation conventions (spike 1.4)

Findings from studying `github/codeql`'s generated extractors (Ruby is the canonical
reference: `ruby/ql/lib/ruby.dbscheme`, generated by `shared/tree-sitter-extractor`,
mirrored in QL by `.../ast/internal/TreeSitter.qll`). Our generator maps Libadalang's
node model (`schema/lal-nodes.json`) onto the same patterns.

## Standard prelude (copy nearly verbatim)

Every language pack carries these tables; the CLI expects several of them:

| Table | Purpose |
|---|---|
| `locations_default(id, file, beginLine, beginColumn, endLine, endColumn)` | one row per distinct location |
| `files(id, name)` / `folders(id, name)` / `containerparent(parent, child)` | file tree |
| `empty_location(location)` | synthetic location for whole-file/unlocated elements |
| `sourceLocationPrefix(prefix)` | snapshot root path |
| `diagnostics(id, severity, error_tag, error_message, full_error_message, location)` + `case @diagnostic.severity of 10 debug / 20 info / 30 warning / 40 error` | extraction errors (parse failures, nameres failures) |
| `databaseMetadata(metadataKey, value)` | emitted by the CLI itself |
| `overlayChangedFiles(path)` | overlay/incremental support, emitted by the CLI |

## Per-node-kind patterns (Ruby → Ada mapping)

With `<k>` a concrete node kind (lowercased, e.g. `subp_body`) and prefix `ada_`:

1. **Kind table**: `ada_<k>_def(unique int id: @ada_<k>, <required fields inline>)`.
   Required (never-null) syntax fields are columns of `_def`, typed by field-type unions.
2. **Optional fields**: one table per field:
   `ada_<k>_<field>(unique int parent: @ada_<k> ref, unique int value: @<type> ref)`.
   Libadalang fields are nullable in general → most Ada fields go this route. LAL's
   "Maybe" nodes (e.g. `AbortAbsent/AbortPresent`, `*Absent/*Present` pairs) stay as
   real nodes; do not flatten them to booleans in v1 (keeps generator uniform).
3. **List children**: LAL list nodes (`is_list_node`) get
   `#keyset[parent, index]` + `ada_<k>_child(int parent ref, int index: int ref, unique int child ref)`.
4. **Field-type unions**: `@ada_<k>_<field>_type = @ada_x | @ada_y | ...` computed from
   the LAL field's precise type (the concrete subtypes of the field's declared class).
5. **Class hierarchy**: LAL abstract classes become union types:
   `@ada_expr = @ada_bin_op | @ada_call_expr | ...` (direct subclasses, recursively).
   This is *better* than tree-sitter's flat `underscore` supertypes — LAL gives us a real
   single-inheritance hierarchy, so the QL class hierarchy falls out naturally.
6. **Token nodes**: LAL token nodes (`is_token_node`, e.g. `Identifier`, `CharLiteral`)
   keep per-kind tables but add a `string value` column in `_def` (source text).
   A single `ada_tokeninfo` like Ruby's is unnecessary — LAL token nodes are typed.
7. **Umbrella relations** over `@ada_ast_node = <union of all kinds>`:
   - `ada_ast_node_location(unique int node ref, int loc: @location_default ref)`
   - `#keyset[parent, parent_index]` + `ada_ast_node_parent(unique int node ref, int parent ref, int parent_index)`

## Semantic layer (ours; no Ruby equivalent — Ruby computes in QL)

Tree-sitter languages have no compiler semantics; we do. Add:

- `ada_xref(unique int ref_node: @ada_name ref, int decl: @ada_basic_decl ref)` —
  from `p_referenced_decl`.
- `ada_expr_type(unique int expr: @ada_expr ref, int type_decl: @ada_base_type_decl ref)` —
  from `p_expression_type`.
- `ada_generic_instantiation(int inst ref, int generic_decl ref)`.
- `ada_body_part(unique int decl: @ada_basic_decl ref, int body: @ada_basic_decl ref)` —
  from `p_body_part`; the declaration-to-completion (call graph) edge, extracted rather
  than inferred from name text because Ada overloading makes textual pairing unsound
  (D-021, Phase 9).
- nameres failures logged into `diagnostics` with a dedicated `error_tag`.

## QL side

Generated `TreeSitter.qll`-equivalent (`ast/internal/Raw.qll`): one QL class per node
kind/abstract class, `getField()` accessors reading the tables, `toString()` = kind name.
Hand-written user-facing layer wraps it (as Ruby wraps TreeSitter.qll in `ast/*.qll`).

## Generator plan (Phase 2)

Input: `schema/lal-nodes.json`. Outputs, from one Python generator (`generator/gen.py`):
1. `ada.dbscheme` (prelude verbatim + generated tables),
2. `extractors/ada/tools/` TRAP-emitter tables module (kind → table/field writers),
3. `ql/lib/codeql/ada/ast/internal/Raw.qll`.
Check all three into git (generated-but-committed, like github/codeql does) so the packs
build without running the generator.
